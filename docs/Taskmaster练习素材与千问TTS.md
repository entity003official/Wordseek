# Taskmaster 练习素材与千问 TTS 实施说明

## 1. 已实现范围

练习页现在提供 10 条真实任务型英语对话，来自项目内 `Taskmaster-master/TM-1-2019/woz-dialogs.json`。选择标准是：对话中的 `ASSISTANT` 话轮可以直接作为学习者的回应练习题；不包含姓名、电话、地址等个人内容；覆盖常见服务交流；题目长度适合一次朗读。

| 分类 | 数量 | 练习内容 |
|---|---:|---|
| 汽车维修 | 2 | 描述故障、确认送修时间 |
| 餐饮点单 | 2 | 确认咖啡门店、选择披萨配料 |
| 餐厅预订 | 2 | 描述理想餐厅、确认餐桌预订 |
| 电影票务 | 2 | 处理场次售罄、选择更早场次 |
| 出行叫车 | 2 | 确认接车时间、说明乘车人数 |

每条素材保留数据集名、`instruction_id`、`conversation_id`、零起始话轮编号和许可。后端启动时校验必须恰好为 10 条、ID 唯一、5 类各 2 条。前端传回 Taskmaster ID 创建练习时，后端用自己的素材库覆盖标题、题目、提示和评分标准，不能通过修改浏览器请求伪造来源内容。

## 2. 来源与许可

Taskmaster-1 由 Bill Byrne、Karthik Krishnamoorthi、Chinnadhurai Sankar、Arvind Neelakantan、Amit Dubey、Kyu-Young Kim、Andy Cedilnik 等作者发布，项目内版权说明将数据置于 Creative Commons Attribution 4.0 License。当前选用 `woz-dialogs`，这是 Wizard-of-Oz 方法收集的双人任务对话。来源归属、原对话 ID 和许可信息保留在服务端素材文件与本说明中，不占用学习者的主练习界面。

为朗读清晰，展示文本只规范化了句首大小写、标点、时间写法和少量明显的大小写错误；语义没有改写。原始文本和完整出处仍保留在项目内数据集。

## 3. TTS 调用与数据边界

- 模型：`qwen3-tts-flash`
- 音色：`Cherry`
- 语言：`English`
- 服务：阿里云百炼 DashScope 多模态生成 HTTP 接口
- 鉴权：复用部署方统一配置的千问 Key，普通用户不填写 Key
- 触发：仅在用户点击“播放题目”时调用
- 输入：当前英文题目，最长 500 字符
- 不发送：用户回答录音、历史转写、账号资料、会话正文

千问返回临时音频地址后，API 立即在服务端下载音频，检查大小和媒体类型，再保存到项目私有对象存储。浏览器收到的是自有 API 返回的音频字节，不会收到千问 Key 或供应商临时地址。日志不记录题目正文、Key 和音频 URL。

缓存键由模型、音色、语言和规范化文本共同计算，数据库只保存 SHA-256 输入哈希与运行元数据。缓存对象按 `tts/<owner_id>/<hash>.<ext>` 隔离；删除 AI 内容、全部数据或账号时同步删除对象。默认每位用户滚动 24 小时最多生成 30 条新语音，已缓存语音可以继续播放且不重复计费。

## 4. 接口

### `GET /api/v1/practice-library`

要求登录。返回 10 条素材、5 个分类和统一归属信息，不返回本地文件路径。

### `POST /api/v1/practice/tts`

要求登录和 CSRF，JSON 请求为 `{ "text": "..." }`。成功响应直接返回 `audio/*`；响应头包含实际模型、音色和 `hit/miss` 缓存状态。鉴权、权限和参数错误不可重试；网络超时、HTTP 429 和 5xx 最多重试 3 次。

## 5. 自动测试

自动测试覆盖：

- 素材总数、分类数量、每类数量、来源许可；
- Taskmaster ID 对应内容由服务端固定；
- Qwen3 TTS 官方 HTTP 请求结构；
- 服务端下载合成音频而不是转发临时 URL；
- 认证错误不暴露供应商响应正文；
- 首次合成缓存未命中、第二次播放命中且不再次调用千问；
- 前端 TypeScript 构建和现有用户、管理、语音流程回归。
