# Beyond Words 企业级优化实施与验收计划

更新时间：2026-09-26  
适用版本：企业版 v1

## 一、项目要解决的事情

Beyond Words 帮助英语学习者把一段真实的一人或多人英语对话，变成可核对、可复盘、可练习的学习资料。产品不做人格判断，也不凭一次对话给用户贴“英语水平”标签；所有结论都必须能指回原始话轮证据。

最基础的闭环只有六项：

1. 录制或上传一段真实英语对话，并允许用户标记重要时刻。
2. 把音频转成带时间戳的英文文本。
3. 自动分离说话人，再由用户确认哪一位是自己。
4. 基于话轮计算发言占比、追问、承接、澄清等可解释指标。
5. 经用户授权后，用 DeepSeek 生成复盘总结、场景判断和带证据的改进建议。
6. 根据真实对话生成三道练习题，并保存回答和反馈，形成下一次练习入口。

## 二、六项功能在四个主界面中的位置

| 主界面 | 用户看到的入口 | 对应基础功能 | 具体子页面 |
|---|---|---|---|
| 首页 | “开始一段对话”、最近对话 | 1 | 录音页 `/recording` |
| 复盘 | 历史列表、转写时间线、说话人确认、互动洞察、AI 复盘 | 2、3、4、5 | 历史 `/history`、复盘 `/review/:sessionId`、互动时刻 `/moment/:sessionId/:eventId` |
| 练习 | 练习卡、回答输入、录音转写、反馈 | 6 | 练习 `/practice`、指定事件练习 `/practice/:eventId` |
| 我的 | 学习目标、AI 授权、隐私和数据、账号管理 | 支撑全部六项 | 我的 `/profile`、数据 `/data`、管理员 `/admin/users` |

登录、注册和找回密码属于进入系统前的账号界面，不占四个主导航位置。

## 三、企业级目标与实际落地

| 领域 | 原型问题 | 已落地方案 | 验收证据 |
|---|---|---|---|
| 前端数据 | 页面各自请求，缓存和重试不统一 | React + TypeScript；TanStack Query 管理接口缓存；Zustand 管理本机交互状态 | 前端单元测试与生产构建 |
| 视觉与交互 | 按钮状态和空状态不清楚 | 中文界面、四项底部主导航、加载/失败/空状态、危险操作二次确认 | 浏览器端到端验收 |
| 代码结构 | API、数据库、任务逻辑集中 | API、Service、Repository、Model、Worker 五层 | `backend/app` 目录与导入边界 |
| 数据库 | SQLite + 原生 SQL | 生产 PostgreSQL；开发隔离 SQLite；SQLAlchemy 2 ORM | API 测试、Compose 配置 |
| 数据库变更 | 启动时建表或改表 | Alembic 显式版本迁移；当前 head 为 `20260926_0004`；开发自动建表仅供本机 | 在全新临时库执行 upgrade/downgrade/upgrade |
| 音频存储 | 本机目录 | S3 兼容接口；容器使用私有 Silo（MinIO API 兼容）；五分钟预签名下载 | 存储适配器、Compose、所有权校验 |
| 后台分析 | API 线程内后台任务 | Redis + Celery；普通 AI 队列与 speech 队列分开 | 任务表、Worker、恢复未完成任务 |
| 模型执行 | API 进程加载模型 | 千问是唯一生产语音 Provider；轻量 `worker-qwen` 并发 2，API 进程不加载语音模型 | Provider 契约、任务恢复、队列配置、真实语料评测 |
| 用户系统 | 无账号 | 邮箱密码、Argon2id、不透明会话、HttpOnly Cookie、CSRF；可选 OIDC | 账号 API 与安全测试 |
| 数据隔离 | 共用数据 | 会话、任务、练习、回答、AI 结果全部带 `owner_id` | 双账号越权测试 |
| 接口版本 | `/api/...` | 全部业务接口为 `/api/v1/...` | OpenAPI 与旧接口升级提示 |
| 大模型 | 无统一语义模型 | 后端统一调用 `deepseek-flash`；用户不填写 Key；按账号授权、脱敏、限额、缓存和证据校验 | 模拟返回测试与真实 API 冒烟测试 |
| 运行监控 | 无统一监控 | JSON 日志、Request ID、OpenTelemetry trace/metric、Prometheus 出口 | 中间件、Collector 配置 |
| 部署 | 手动运行 | Web/API 两类镜像、Compose、健康检查、Caddy HTTPS、CI、GHCR 发布和环境审批部署；Qwen Worker 复用 API 镜像 | Compose 解析、镜像构建工作流 |
| 安全 | 基础 CORS | HTTPS、HSTS、CSP、限流、CSRF、私有对象、审计日志、Secret 文件挂载 | 安全配置与测试 |

## 四、DeepSeek API 执行口径

API Key 属于部署方，不让每个普通用户填写。演示环境从 `api-key/api-key.txt` 读取；该路径被 Git 和 Docker 构建上下文排除。生产通过 Compose Secret 只读挂载到 `/run/secrets/deepseek_api_key`。

调用方式固定为：

```text
POST https://api.deepseek.com/chat/completions
Authorization: Bearer <server-managed-key>
model: deepseek-flash
thinking.type: disabled
response_format.type: json_object
```

模型使用位置：

| 功能 | 输入 | 结构化输出 | 失败处理 |
|---|---|---|---|
| 复盘总结 | 脱敏话轮、场景提示、学习目标 | 标题、摘要、主题、证据话轮、限制 | 返回可重试错误，本地指标仍可查看 |
| 场景分析 | 同上 | 场景类型、沟通目标、证据、置信度 | 拒绝不存在的话轮引用 |
| 互动洞察 | 已确认“哪位是我”的话轮 | 观察、语境、建议、英语示例、证据 | 未确认本人时不生成针对性事件 |
| AI 出题 | 话轮和所选互动事件 | 固定三题、提示、参考回答、评分标准 | 后台任务失败可重试 |
| 回答反馈 | 单题、评分标准、用户回答 | 优点、改进、逐项评分、改写、下一问 | DeepSeek 不可用时回退到本地透明规则 |

系统只发送脱敏文本，不发送音频。邮箱、电话、网址、长身份编号和用户配置的姓名别名会先替换；复盘页提供发送前预览。模型输出必须通过 Pydantic 结构校验和证据 ID 白名单校验后才能入库。

## 五、账号与权限设计

| 角色 | 能做什么 | 明确不能做什么 |
|---|---|---|
| 未登录访客 | 注册、登录、发起密码找回 | 读取任何业务数据 |
| 普通用户 | 管理自己的会话、音频、练习、AI 授权、导出和删除 | 读取其他账号的数据 |
| 管理员 | 查看账号状态和用量、冻结/启用账号、撤销登录会话 | 默认读取用户录音、转写和 AI 内容 |

密码使用 Argon2id 哈希。浏览器保存的是 HttpOnly 会话 Cookie，不把访问令牌放进 `localStorage`。所有修改请求还需要可读 CSRF Cookie 与请求头一致。会话同时有空闲失效和绝对失效时间；改密码、管理员撤销或冻结账号都能使会话失效。

## 六、数据与任务流

```text
浏览器录音/上传
  → API 校验当前账号、格式和大小
  → 私有对象存储
  → 持久化 AnalysisJob
  → Redis speech 队列
  → worker-qwen（并发 2、预取 1）
  → 每段录音单独授权千问音频处理
  → 千问 Filetrans 转写与自动 1–8 人分离
  → 千问任务 ID 入库，Worker 重启继续轮询原任务
  → 用户确认本人
  → 本地指标和透明规则提示
  → 用户选择授权 DeepSeek
  → AI 任务队列
  → 结构校验、证据校验、结果缓存
  → 复盘与三题练习
  → 回答、反馈、再次练习
```

Qwen Worker 崩溃不会丢任务：任务状态保存在数据库，Worker 使用 late acknowledgement，API 重启时会重新派发未完成任务。千问任务 ID 在提交后立即入库，恢复时不重复提交。超时、限流和 5xx 最多重试三次；Key、权限和参数错误直接呈现。任何错误都不会回退旧本地模型或生成模拟结果。DeepSeek 请求按输入哈希和提示词版本缓存，避免相同内容重复计费。

## 七、验收清单

### 自动验收

运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify_enterprise.ps1
```

该命令必须同时通过：

- API Key 路径隔离，且没有密钥内容进入源码。
- 前端单元测试。
- TypeScript 检查和 Vite 生产构建。
- 后端 20 项以上的账号、CSRF、所有权、Qwen 边界、AI 结构和算法测试。
- 全新数据库的 Alembic upgrade、downgrade、再次 upgrade。
- 默认生产 Compose 与本地用户验收 Compose 配置解析。
- `127.0.0.1:18080` 同源入口、注册会话、Cookie、CSRF 与API私有端口验证。

### 人工验收

1. 打开 `/register` 创建账号，密码不足 12 位必须被拒绝。
2. 登录后四个主导航均可进入；刷新页面仍保持登录。
3. 新建录音，开始、标记、结束、保存都要有明确状态。
4. 转写完成后必须先确认本人，说话人和文本允许修正。
5. 未授权 AI 时按钮给出明确说明；授权后预览中不出现可识别邮箱或电话号码。
6. AI 复盘完成后能看到摘要、场景、证据和互动建议。
7. 生成练习后固定得到三题；提交回答能看到反馈并保存。
8. 第二个账号看不到第一个账号的会话。
9. 数据导出包含自己的会话、练习、回答和 AI 结果；删除数据后列表为空。
10. 管理员可以冻结账号，但没有内容浏览入口。

## 八、部署前必须由环境提供的内容

代码层已经完成，但以下值不应写死进仓库，部署者必须在目标环境配置：

- 真实域名及 DNS。
- PostgreSQL、S3 兼容对象存储、会话密钥的随机生产密码。
- DeepSeek 生产 API Key Secret。
- 百炼生产 API Key Secret；如使用专属域名，同时配置 Workspace ID。
- 如需企业登录：OIDC issuer、client id、client secret。
- 如需找回密码邮件：SMTP 地址与凭据。
- GitHub Production Environment 的部署主机、端口、用户、路径和 SSH Key。

这些是外部环境凭据，不属于代码缺口。生产缺少百炼 Key 时，就绪检查直接失败，不会启动一个无法转写的伪正常服务。

## 九、交付物边界

源码交接 ZIP 包含源码、旧本地语音归档、锁定依赖、数据库迁移、容器和监控配置、自动测试、评估数据说明与导入工具、中文文档。生产部署包会排除 `archive/`。以下内容故意不打包：

- `api-key/` 和 `.env`：真实密钥。
- `.venv/`、`node_modules/`、`.npm-cache/`、`.pip-cache/`：机器相关且可重新安装的依赖。
- `dist/`、`__pycache__/`、测试缓存：可重建产物。
- `backend/data/`：本机数据库和录音，可能包含隐私且体积大。
- `evaluation/raw/`：可从公开来源按文档重新下载的大文件。
- 旧 ZIP 和打包暂存目录。

因此 ZIP 中的每一项都是重建、维护、验收或部署产品所需的可移交内容。
