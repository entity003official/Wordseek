# Beyond Words 本地真实用户验收指南

## 1. 目标

本模式模拟“普通用户的浏览器连接企业 Linux 服务器”。浏览器运行在 Docker 外；生产构建后的 Web、API、Worker、PostgreSQL、Redis、对象存储、网关和监控运行在 Docker 内。

验收时不要启动 Vite，不要单独启动本机 FastAPI，也不要访问 `5173` 或 `8000`。

## 2. 启动

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_user_test.ps1
```

出现以下提示后再打开浏览器：

```text
User-test environment is ready: http://127.0.0.1:18080
```

唯一用户入口：`http://127.0.0.1:18080`

只读就绪检查：`http://127.0.0.1:18080/api/v1/health/ready`

## 3. 真人验收顺序

1. 创建一个自己的验收账号。
2. 退出并重新登录，确认账号会话正常。
3. 允许浏览器使用麦克风。
4. 与另一人各说至少三轮英语并停止录音。
5. 保存录音，确认不同意千问云端处理时不能开始分析。
6. 勾选本次千问处理授权，等待转写和匿名说话人分离完成。
7. 回听并抽查至少五个话轮，确认文字、起止边界和两位说话人大致正确。
8. 选择代表自己的匿名说话人，检查发言占比和话轮数变化。
9. 修改一个话轮文字并刷新页面，确认修改仍然存在。
10. 在“我的”开启 DeepSeek，先查看脱敏预览，再生成复盘与三道练习题。
11. 文字或语音回答一道题，确认反馈来源为 DeepSeek。
12. 退出并重新登录，确认会话、练习和反馈仍然存在。
13. 如需验证隔离，创建第二个账号，确认它看不到第一个账号的数据。
14. 在千问和 DeepSeek 控制台核对本次真实调用用量。

## 4. 自动冒烟

以下命令会创建一次随机测试账号，验证注册、Cookie、CSRF 和当前用户读取，然后立即删除该测试账号：

```powershell
.\.venv\Scripts\python.exe scripts\live_register_smoke.py
```

它不会调用千问或 DeepSeek，不产生模型费用。

## 5. 停止

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop_user_test.ps1
```

该命令停止服务，但保留 PostgreSQL、Redis、对象存储和网关数据卷。再次启动后数据仍在。

## 6. 与正式部署的差异

| 本地用户验收 | 正式 Linux 部署 |
|---|---|
| `http://127.0.0.1:18080` | `https://正式域名` |
| 只允许本机访问 | 面向获准用户访问 |
| 回环 HTTP，避免自签名证书干扰 | 受信任 TLS 证书 |
| Docker 中的 PostgreSQL、Redis、对象存储 | 可替换为企业托管服务 |

其余应用路由、生产前端构建、API、数据库迁移、任务队列、模型调用和账号隔离逻辑保持一致。
