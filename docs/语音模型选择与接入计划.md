# Beyond Words 千问语音接入与收敛实施记录

> 状态：代码改造、自动测试、容器与真实 API 复验均已完成；结果见最终验收报告。  
> 固定决策：千问是唯一生产语音模型，DeepSeek 是唯一生产语义模型。  
> 最后更新：2026-09-26。

## 1. 当前模型边界

| 能力 | 唯一生产实现 | 输入 | 输出 |
|---|---|---|---|
| 会话转写与 1～8 人分离 | `qwen-audio-3.1-asr-flash-filetrans` | 经授权的单声道 16 kHz FLAC | 匿名说话人、句/词时间戳、英文转写、用量 |
| 短练习转写 | `qwen-audio-3.1-asr-flash` | 经授权的短音频 | 文本、模型与用量 |
| 练习题目朗读 | `qwen3-tts-flash` / `Cherry` | 用户主动点击后的英文题目文本 | 私有缓存音频、模型、用量与耗时 |
| 复盘与场景分析 | DeepSeek `deepseek-flash` | 脱敏话轮 | 结构化总结、场景和证据引用 |
| 出题与回答反馈 | DeepSeek `deepseek-flash` | 脱敏话轮或用户答案 | 三道题、评分标准、反馈 |

旧本地语音方案不再是备用 Provider，不参与默认依赖、Compose、生产镜像、测试发现或运行时回退。它只保存在 `archive/local-speech-provider/`，用于历史复现。

## 2. 产品行为

- `POST /api/v1/sessions/{id}/analyze` 由服务器固定选择千问。
- 请求体不公开 `speech_backend`；Pydantic 暂时忽略旧客户端多传的字段，因此升级不会立刻报错。
- 每段录音必须单独提交 `cloud_audio_consent.accepted=true`；授权只对本次分析有效。
- 未授权时录音已保存，但分析接口返回 409，不会在后台偷偷上传。
- 短练习音频同样要求本次千问授权；没有授权时用户仍可文字作答。
- 题目朗读由用户主动点击触发，只发送当前英文题目，不发送用户回答录音；同一题目命中私有缓存时不重复调用模型。
- 千问失败时保存稳定错误码与 `retryable`，前端显示重试或管理员处理入口。
- 任何错误都不会生成模拟转写，也不会切换到旧本地模型。
- DeepSeek 授权与千问授权互相独立；DeepSeek 只接收脱敏文本。

分析请求示例：

```json
{
  "language_hints": ["en"],
  "speaker_policy": {
    "mode": "auto",
    "min_count": 1,
    "max_count": 8
  },
  "cloud_audio_consent": {
    "accepted": true,
    "version": "qwen-cloud-v1"
  }
}
```

旧客户端即使额外传入 `"speech_backend": "local"`，该字段也会被忽略，实际 `requested_backend` 仍记录为 `qwen`。

## 3. 任务执行过程

```text
浏览器上传音频
  → API 按 owner_id 保存到私有对象存储
  → 用户确认本次千问上传授权
  → 创建 AnalysisJob 并投递 speech 队列
  → worker-qwen 下载私有音频到临时目录
  → FFmpeg 转单声道 16 kHz FLAC
  → 获取百炼临时上传地址并上传
  → 提交 Filetrans，立即把 qwen task_id 写入数据库
  → 轮询原 task_id；Worker 重启后从数据库恢复轮询
  → 规范化匿名说话人、话轮、词时间戳和 usage
  → 保存分析快照并删除临时文件
```

活跃实现：

- 千问 HTTP、临时上传、提交、轮询、结果规范化：`backend/app/speech/providers.py`
- 任务恢复、结果结构与失败持久化：`backend/app/services/speech.py`
- Celery 重试：`backend/app/workers/tasks.py`
- 分析接口与逐次授权：`backend/app/api/sessions.py`
- 练习语音：`backend/app/api/practice.py`
- 能力与就绪检查：`backend/app/api/health.py`

## 4. 重试和恢复

| 错误 | 是否重试 | 行为 |
|---|---|---|
| 网络连接、读取超时 | 是 | HTTP 层指数等待；作业层最多再试三次 |
| HTTP 429 | 是 | 最多三次，前端可看到可重试状态 |
| HTTP 5xx | 是 | 最多三次 |
| 千问任务临时轮询失败 | 是 | 保留原 `task_id`，重启后继续查询 |
| 千问任务明确终止 | 视服务返回而定 | 若允许重试则清除已终止任务 ID 后重新提交 |
| Key 缺失或无效 | 否 | `QWEN_AUTH_ERROR`，要求管理员处理 |
| 权限、工作空间或参数错误 | 否 | 稳定错误码，要求管理员处理 |
| 音频格式或 FFmpeg 失败 | 否 | 明确提示录音处理失败 |

HTTP 请求的 `BEYOND_WORDS_QWEN_MAX_RETRIES=3` 表示初始尝试后最多重试三次。Celery 任务同样配置最多三次作业级重试，以覆盖 Worker 进程中断等情况。为避免重复付费，只要任务 ID 已保存，恢复路径就跳过上传和提交。

## 5. 持久化结果约定

分析快照中的 `execution` 至少保存：

- `provider: "qwen"`；
- 实际模型名；
- 千问 `provider_task_id`；
- 音频时长与端到端处理耗时；
- 千问返回的 usage/Token 字段；
- Provider HTTP 重试次数；
- `resumed_existing_task`，标识是否从已有任务恢复。

作业表保存 `error_code`、`retryable`、尝试次数和最终错误摘要。日志只记录请求 ID、用户私有标识、作业 ID、状态和稳定错误码，不记录 API Key、临时音频 URL 或完整转写。

API、Qwen Worker 与 AI Worker 均将 `httpx/httpcore` 的请求级日志限制为 WARNING，避免依赖库在 INFO 日志中输出带签名地址或供应商请求详情。

## 6. Docker 结构

默认 `docker-compose.yml`：

| 服务 | 职责 |
|---|---|
| `web` | React 静态站点 |
| `api` | FastAPI 与 Alembic 启动迁移 |
| `worker-qwen` | 监听 `speech`，并发 2、预取 1 |
| `worker` | 监听 `default`，执行 DeepSeek 等普通任务 |
| `postgres` | 主数据与任务状态 |
| `redis` | Celery Broker、状态和限流 |
| `minio` | Silo 提供的 S3/MinIO 兼容私有对象存储 |
| `gateway` | Caddy HTTP/HTTPS 入口 |
| `otel-collector` | 指标与链路收集 |

后端镜像只安装 FFmpeg 和普通业务依赖，不包含 PyTorch、CUDA 或旧语音依赖。Docker 用于开发、验收和服务器部署；终端用户不需要安装。
