# Beyond Words 技术架构与功能实现

本文描述当前企业版代码，不包含已经归档的旧本地语音运行方式。

## 1. 总体架构

```text
React Web
  ├─ 麦克风 / MediaRecorder / 波形与标记
  ├─ IndexedDB 录音副本
  ├─ TanStack Query 接口缓存
  ├─ Zustand 本地交互状态
  └─ /admin 独立桌面管理区
          │ /api/v1 + HttpOnly Cookie + CSRF
          ▼
FastAPI API
  ├─ Auth / Session / Practice / Admin API
  ├─ Service + Repository + SQLAlchemy Model
  ├─ PostgreSQL + Alembic
  ├─ 私有 S3 兼容对象存储
  └─ Redis / Celery
       ├─ speech → worker-qwen → Qwen Filetrans/Flash
       └─ default → worker → DeepSeek deepseek-flash

OpenTelemetry Collector → Prometheus → Grafana
                         ├─ PostgreSQL exporter
                         ├─ Redis exporter
                         └─ Flower / Celery
```

Caddy 提供统一入口和生产 HTTPS，OpenTelemetry Collector 接收链路与指标。Prometheus 仅在容器网络中持久化采集，Grafana 在用户测试环境单独绑定回环地址，生产环境不经过公共 Caddy 暴露。所有业务记录均带 `owner_id`；内容查询以当前登录用户为边界。

## 3. 后端分层

| 层 | 目录 | 责任 |
|---|---|---|
| API | `backend/app/api/` | 校验、权限、HTTP 状态与稳定返回结构 |
| Service | `backend/app/services/` | 语音编排、脱敏、对象存储、认证业务 |
| Repository | `backend/app/repositories/` | 带 owner 范围的数据查询 |
| Model | `backend/app/models.py` | SQLAlchemy 2 持久化模型 |
| Worker | `backend/app/workers/` | Celery 队列、重试和后台执行 |
| Provider | `backend/app/speech/`、`backend/app/ai/` | 千问和 DeepSeek 协议适配 |

数据库变更只通过 `backend/migrations/versions/` 中的 Alembic 迁移执行。生产设置 `BEYOND_WORDS_AUTO_CREATE_SCHEMA=false`，不会在应用启动时使用临时 `CREATE TABLE` 代替迁移。

## 4. 六项核心功能如何实现

### 4.1 录音与保存

浏览器用 `MediaRecorder` 采集音频，并先保存到 IndexedDB。API 创建会话后将音频写入私有对象存储，数据库只保存对象键、时长、MIME 和所有者，不暴露磁盘路径。录音标记作为独立 `Marker` 记录保存。

### 4.2 千问转写、说话人分离与语音合成

用户提交本次云端授权后，API 创建 `AnalysisJob` 并投递 `speech` 队列。Worker 用 FFmpeg 转成 16 kHz 单声道 FLAC，提交 Filetrans 并立即保存任务 ID。结果被规范化为匿名 speaker、turn 和 word 时间戳。1～8 人为默认范围，用户明确人数时可固定。

### 4.3 本人确认与修正

千问只输出匿名说话人。用户通过复盘页选定自己的 speaker ID；后端重新计算个人发言时长、占比和话轮数。单条话轮可以修改文本或说话人，修改后重新生成可解释指标。

练习题目的英文朗读使用 `qwen3-tts-flash` 和系统音色 `Cherry`。浏览器只把题目文本发送给自有 API；API 调用千问后立即下载音频并写入私有对象存储，不把供应商临时 URL 或 Key 返回前端。`ai_generations` 记录 `provider=qwen`、模型、音色、usage、耗时、重试次数和对象键，但不保存题目正文。输入哈希实现同用户同题复用，每位用户默认 24 小时最多生成 30 条新音频。

### 4.4 指标与证据提示

`backend/app/services/speech.py` 根据时间线计算发言占比、话轮、提问、承接和澄清等透明规则。每条事件包含原话轮 ID 与时间范围，用户可以回听证据。规则结果不冒充大模型结论。

### 4.5 DeepSeek 复盘与场景分析

开启 AI 授权后，服务用 `backend/app/services/redaction.py` 替换邮箱、电话、网址、长编号和用户别名，再调用 `deepseek-flash` 的结构化 JSON 输出。Pydantic 验证结构，服务验证所有 evidence turn ID，按输入哈希缓存结果并记录模型用量。

### 4.6 出题与回答反馈

DeepSeek 基于同一会话的脱敏证据生成恰好三道题、提示和评分标准。练习页也提供 10 条经过来源核对的 Taskmaster-1 WOz 任务对话，按 5 个日常服务场景分类。用户可播放千问合成的题目语音并以文字回答；短回答录音只有在逐次授权后才用千问 Flash 转文字。回答反馈优先由 DeepSeek 生成，未开启 AI 时显示来源明确的本地规则反馈。

## 5. 认证、隔离与安全

- 密码使用 Argon2id，服务端只存哈希。
- 登录凭证是随机不透明令牌，数据库存令牌哈希，浏览器使用 HttpOnly Cookie。
- 修改请求必须带 CSRF Token。
- 账号、会话、作业、练习、AI 生成物和审计记录分离。
- 管理员可冻结账号、撤销会话和看聚合用量，但没有通用用户内容读取接口。
- 对象存储保持私有，下载由 API 校验 owner 后生成短时签名地址。
- 结构化日志不记录 Key、音频 URL、提示词或完整转写。

## 6. 语音失败协议

前端通过作业或会话状态看到：`status`、`progress`、`stage`、`error_code`、`retryable` 与 `attempt_count`。可重试错误显示重试入口；鉴权、权限和参数错误提示联系管理员。分析快照的 `execution` 保存 Provider、实际模型、任务 ID、时长、耗时、用量、重试次数和任务恢复标记。

千问任务恢复依赖数据库中已经保存的 task ID，因此 Worker 重启不会重新上传和提交同一音频。只有已经被千问明确终止且允许重试的任务才清空旧 ID 后重新提交。

## 7. 部署与运行边界

默认 Docker 后端镜像基于普通 Python 运行时，只安装 FFmpeg 和 `backend/requirements.txt`。`worker-qwen` 与 API 共用镜像；它是网络型 Worker，不需要 GPU。普通 Worker 处理 DeepSeek 等默认队列任务。

旧本地语音代码位于 `archive/local-speech-provider/`，只随源码交付，不进入生产部署包、Docker 构建上下文或默认测试。默认 Compose 也不存在语音 GPU 设备配置。

本地真实用户验收使用 `docker-compose.user-test.yml` 叠加配置。浏览器只访问 `http://127.0.0.1:18080`；网关在容器网络内分别代理生产构建的 Web 与 API。API 的 `8000`、数据库、Redis 和对象存储端口均不向用户侧开放。该模式模拟“用户设备 → 企业服务器”，并避免把 Vite 开发代理误当成生产入口。

## 8. 管理后台

`/admin/*` 使用与用户端相同的 `AuthContext`、HttpOnly Cookie 和 CSRF，但拥有独立的 `AdminLayout`，不会显示手机端底部导航。未登录访问会进入独立的 `/admin/login` 管理员登录页，普通用户会看到明确的无权限说明与切换账号入口，管理员进入 `/admin/overview`。真正的权限边界仍由 `current_admin` 依赖在每个 `/api/v1/admin/*` 接口执行。

| 接口 | 作用与隐私边界 |
|---|---|
| `GET /admin/overview` | 用户、会话、任务和 Provider 聚合趋势 |
| `GET /admin/users` | 搜索、角色、状态与分页，不返回密码或内容数据 |
| `GET /admin/jobs` | 按类型、状态、Provider 和起止日期筛选，只返回任务元数据、耗时、错误码和重试性 |
| `POST /admin/jobs/{id}/retry` | 保留原失败任务并创建带 `retry_of_job_id` 的新任务 |
| `GET /admin/model-usage` | 聚合 Qwen 与 DeepSeek 的应用侧 usage |
| `GET /admin/audit-logs` | 只返回白名单审计元数据 |
| `GET /admin/system-health` | 无付费调用地检查基础服务、Worker 和配置 |

重试仅允许 `failed + retryable` 的任务；同会话同类型已有排队或运行任务时拒绝重复创建。管理员重试写入 `admin.job_retried`，原失败记录不修改。后台不提供录音、转写正文、任务输入、模型完整输出、模拟用户或删除用户数据功能。

TanStack Query 对概览、模型用量和健康状态按 15 秒刷新；任务列表只有存在排队/运行任务时才按 10 秒刷新。页面不可见时停止后台刷新。

## 9. 可观测性

- API、普通 AI Worker 和 Qwen Worker 使用不同的 OpenTelemetry `service.name`。
- HTTP 指标标签使用 FastAPI 路由模板，例如 `/api/v1/admin/jobs/{job_id}/retry`，不把真实 ID 写入标签。
- 任务指标只包含任务类型、Provider、结果和稳定错误类型，不包含用户、会话、任务 ID 或正文。
- 应用额外导出 `default`、`speech` 队列长度；Flower 提供 Celery Worker 状态。
- PostgreSQL exporter 和 Redis exporter 只读取基础设施指标。
- Grafana 关闭匿名访问、公开注册和未使用的 Loki Explore 插件；本轮不引入 Loki、Tempo 或 Alertmanager。

Grafana 预置看板位于 `deploy/grafana/dashboards/beyond-words-operations.json`，数据源与看板自动配置位于 `deploy/grafana/provisioning/`。Prometheus 采集规则位于 `deploy/prometheus.yml`。
